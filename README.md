# AEGIS — Agentic Engineering Intelligence for Industrial Systems

**From machine signals to engineering decisions.**

AEGIS analyzes industrial telemetry (temperature, pressure, current, etc.) and produces
an engineering diagnosis in natural language: it profiles the data, detects
anomalous behavior and changes in operating conditions, estimates a health score, explains
what evidence supports it (SHAP, when a trained model is available), and provides
a recommendation along with its confidence level—explicitly distinguishing
**how abnormal something appears** from **how confident the system is in that
conclusion**.


> **Is this an LLM wrapper?** No. The LLM does not make the prediction or decide
> what is anomalous. Statistical and ML models generate the evidence; the
> reasoning agent merely explains it, communicates the uncertainty, and
> translates it into an action.

## Arquitectura

```
                    ┌─────────────────────┐
                    │       AEGIS         │
                    │  Reasoning Agent     │  <- LLM local (Ollama),
                    └──────────┬──────────┘     It only sees the evidence object
                               │
                    ┌──────────▼──────────┐
                    │   Evidence Engine    │  <- pack the evidence
                    └──────────┬──────────┘     into a structured object
                               │
        ┌──────────────────────┼──────────────────────┐
        │                      │                      │
        ▼                      ▼                      ▼
  Data Profiling      Time-Series Engine         ML Engine
  (quality, types,    (features, regime,      (classifier +
   temporary gaps)   anomaly, change-point)   SHAP, if there are
                                                 historical labels)
```

**Two layers:**
- **Layer 1 (unsupervised):** `data_profiling.py`, `time_series_engine.py` ->
  works with **any** dataset containing timestamps and numeric columns. It does not
  require a history of failures.
- **Layer 2 (supervised):** `ml_engine.py`, `explainability.py` -> requires a
  model trained specifically for that asset/dataset. If one does not exist, the
  system explicitly states this rather than inventing a failure probability.

## Project Structure

```
aegis/
├── app.py                  # Dashboard Streamlit (entry point)
├── aegis_core/              # Reusable logic, independent of the dataset
│   ├── data_profiling.py    # automatic profiling + data quality score
│   ├── time_series_engine.py# Features, regime detection, anomaly, change-point
│   ├── ml_engine.py          # Split temporal, AutoML liviano, evaluación
│   ├── explainability.py     # SHAP, health score, confidence
│   ├── evidence_engine.py    # Build the structured evidence object
│   ├── reasoning_agent.py    # Call the local LLM (Ollama) using the anti-hallucination prompt
│   └── pipeline.py           # Set up all of the above for any CSV file
├── scripts/                  # Specific to the training dataset (MetroPT-3)
│   ├── prepare_metropt3.py           # Download/label the real-world dataset (4 documented errors)
│   ├── build_features_metropt3.py    # Run the time-series engine on MetroPT-3
│   ├── train_classifier.py           # Train the production model
│   ├── evaluate_leave_one_out.py      # Honest assessment: train with 3 events, test with 1
│   ├── compute_shap_and_health.py     # SHAP + health score + confidence on the MetroPT-3
│   └── demo_reasoning_cli.py          # Try the reasoning agent from the terminal
├── data/
│   ├── raw/                 # Raw CSV file for MetroPT-3 (download manually; see scripts/prepare_metropt3.py)
│   └── processed/           # Intermediate and final datasets generated by the scripts
└── models/                   # Trained model (.joblib) + feature columns (.json)
```

**Why this separation:** `aegis_core/` is the product—it’s what makes
“you upload any CSV and AEGIS analyzes it” true. `scripts/` is how the
specific demo model (MetroPT-3) was built and validated; it is not part of the
product itself.

## Setup instructions

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate      # macOS/Linux

pip install -r requirements.txt
```

You also need [Ollama](https://ollama.com/download) installed and running,
with at least one model downloaded:
```bash
ollama pull llama3.2:3b
```

## How to use it

### Option A — Dashboard with your own dataset (what is being pitched as a product)

```bash
streamlit run app.py
```

Select “Upload My Own CSV” in the sidebar. It requires a
date/time column and at least one numeric sensor column. AEGIS performs
profiling, feature engineering, regime/anomaly/change-point detection, and
generates a diagnosis—without requiring a model trained on that specific
dataset.

### Option B — Dashboard with the MetroPT-3 demo (using a trained model)

First, you need to build the dataset and the model (just once):

```bash
    python scripts/prepare_metropt3.py          # Download and tag (see instructions within the script)
python scripts/build_features_metropt3.py
python scripts/train_classifier.py
python scripts/compute_shap_and_health.py
```

Then:
```bash
streamlit run app.py
```
And select “Demo: MetroPT-3” from the sidebar.

### Option C — Model evaluation only (without dashboard)

```bash
python scripts/evaluate_leave_one_out.py
```

## Known limitations

- The demo dataset (MetroPT-3) contains only **4 real failure events**. The
  supervised classification generalizes well to long/severe failures
  (PR-AUC ~0.8) but poorly to short, never-before-seen failures (PR-AUC ~0.02) — see
  `scripts/evaluate_leave_one_out.py` for details by event. This is a
  sample size limitation, not a design limitation.
- The health score is a **prototype heuristic score** (weights set a
  priori, documented in `aegis_core/explainability.py` and
  `aegis_core/pipeline.py`), not a validated industry metric.
- For datasets uploaded without a labeled failure history, there is no
  supervised failure probability—the system explicitly states this.
